PROJECT CONTEXT
FurniSpace: Furniture for Modern Living. It is a college e-commerce project with three defining capabilities:
1. Online shopping for new furniture.
2. A moderated second-hand furniture resale marketplace.
3. "Complete My Room", which recommends a furniture bundle based on room type, style and budget.

The attached project synopsis is the source of truth for the project scope. Preserve its stated stack and boundaries: HTML, CSS, JavaScript, Python Flask and SQLite. Orders are demo orders. There is no real payment gateway or delivery service.

REQUIRED FEATURES

A. AUTHENTICATION
- Register, login, logout.
- Hash passwords; never store plaintext.
- Roles: customer and admin.
- Public registration must always create customer accounts.
- Protect admin routes server-side with role checks.
- Seed a demo admin account and document its login credentials in README.
- Use Flask sessions and sensible flash messages.

B. NEW FURNITURE SHOP
- Seed at least 18 useful sample products across sofas, beds, tables, chairs, wardrobes, storage, lighting and decor.
- Product fields: name, category, description, price, material, colour, dimensions, stock, image, suitable room types, style and active flag.
- Product listing, detail, search by name, category filter, price filter and sorting.
- Product cards show image, name, price and clear actions.
- Show out-of-stock state and validate requested quantity against stock on the server.
- Use attractive, reliable image assets. If external image URLs are used, provide graceful fallbacks. Do not let broken images ruin the layout.

C. PRODUCT COMPARISON
- Compare up to three selected products.
- Display price, category, material, colour, dimensions and availability side by side.
- Allow removing items and clearing comparison.
- Store selections in session; do not require a complex comparison database model.

D. RESALE MARKETPLACE
- Logged-in customers can submit a used furniture listing with title, description, category, asking price, condition, location/contact details and image.
- Prefer safe local image uploads with allowed image extensions and secure filenames. Set a reasonable upload size limit. If upload implementation creates a serious blocker, use a validated image URL and document the limitation.
- New listing status must be Pending.
- Sellers can view their own listings and statuses.
- Admin can approve or reject listings.
- Only Approved listings may be visible publicly.
- Never trust a client-supplied listing status.

E. COMPLETE MY ROOM
- Inputs: room type (Bedroom, Living Room, Study Room, Dining Room), budget and style (Modern, Minimalist, Traditional, Contemporary).
- Implement a deterministic Python rule-based recommendation algorithm. Do not require an external AI API.
- Use active, in-stock products and their room/style/category attributes.
- Choose a sensible combination of essential furniture categories for the room, staying at or below the budget.
- Display recommended items, individual prices, total cost and remaining budget.
- Allow replacing/removing items and recalculate totals.
- Allow adding the generated bundle to cart.
- Never exceed the chosen budget. If no suitable combination exists, show a clear message and useful alternative guidance.
- If style matches are insufficient, relax style matching transparently but preserve the budget.
- Keep the algorithm readable and explain it briefly in README.

F. CART, CHECKOUT AND ORDERS
- Add to cart, update quantity, remove item and display subtotal/total.
- Validate stock and totals on the server, never trust browser-submitted prices.
- Checkout collects customer name, phone and delivery address.
- Clearly label this as a demo checkout/simulated payment. Do not collect card details.
- Create Order and OrderItem records in a database transaction.
- Store each item's unit price at purchase time.
- Reduce stock safely; prevent negative stock.
- Clear cart only after successful order creation.
- Display order confirmation and unique order ID.
- Customers can view only their own orders and order details.
- Admin can update order status: Placed, Confirmed, Shipped, Delivered or Cancelled. Handle cancellation/stock restoration consistently.

G. ADMIN DASHBOARD
- Protect all admin routes on the server.
- Dashboard counts must come from the database: users, active products, orders and pending resale listings.
- Add/edit/deactivate products and update stock.
- View orders and update their status.
- Approve/reject resale listings.
- Keep the dashboard clear, compact and usable.

- Consistent header, navigation, footer, cards, forms and buttons.
- Responsive desktop and mobile layouts.
- Clear empty states, loading/validation/error messages and confirmation messages.
- Keep animations subtle and optional.
- Use one consistent visual system across customer and admin pages.
